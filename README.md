# 启明（Qiming）· 本机智能体

独立的本机智能体工程：**TypeScript 后端（Node 22，零构建）+ React 前端**，自己的服务、自己的端口、自己的数据目录。
不依赖文档站，也不随它启动。

- 后端零构建：Node 22 的原生类型剥离直接跑 `.ts`（类型检查用 `npm run typecheck`）
- 前端 React 19 + Tailwind 4 + esbuild（`npm run build:ui`）
- 数据全在工程内的 `data/`；一个账号都没有 —— **登录就是本机账号登录**

## 运行中还能说话：排队

运行中发的消息**先排队**（对齐主流做法：Codex 的 Enter 入队、Claude Code 的打字排队）：

- 排队条在**输入框上方**（可折叠），一条条列着；每条可以「**立即执行**」（打断当前模型调用、插到最前，
  等价 Codex 的 `instant_interrupt`）或**删除**；
- **排队中的消息不进消息区** —— 没执行的消息不该出现在对话里；被取走执行时服务端发 `msg` 事件，
  那时它才作为一条正常用户消息落进转录；
- 这一轮跑完还没被单独处理的，**轮次边界自动交给模型**；运行结束时队列里还有剩的，会**自动接着开下一段**
  （所以排队不会永远挂着）；
- 队列是**服务端**的：刷新、换设备、另一个标签页排的队都能看到（广播 `queued` 事件 + 会话详情带队列）。

```bash
cd /media/leo/DATA/workspace/qiming
bash up.sh            # 默认 0.0.0.0:8787；首次会自动构建前端
```

打开 `http://127.0.0.1:8787/`，用**本机账号 `leo` 的密码**登录（校验方式就是 `sudo -v`，
所以能登进来 = 这台机器认你，且你有 sudo 权限）。登录后：

- 到「设置 → 模型」加一个服务商（Base URL + 模型名 + API Key），例如

## 四个模块

| 模块 | 是什么 | 在哪里 | 模型怎么用 |
|---|---|---|---|
| **插件** | 提示词 + 可执行命令（工具） | 「设置 → 插件」 | 提示词注入系统消息，工具进工具表 |
| **记忆** | AI 工作的重要记录事项 | 「设置 → 记忆」 | 索引常驻，`memory_read` 取全文 |
| **技能** | AI 工作的具体方法（SKILL.md） | 「设置 → 技能」 | 目录常驻，`use_skill` 载入全文 |
| **外部资源** | 本机可调用的外部能力 | 「设置 → 外部资源」 | 工具进模型工具表（界面上只归资源页） |

四块都**可读可写**：提示词能在界面上直接改（改完下一个模型步生效，进行中的会话同样生效），
参数由你定（**服务端不设硬上限**，填多少就是多少）。

另外两个菜单：

- **项目**：工作区（放项目的根目录）+ 项目列表。**一切项目都在工作区之下** ——
  目录选择器只在工作区内浏览、到工作区根就没有"上一层"，服务端接口也会再校验一遍。
  项目可改名、可改路径（不搬动磁盘文件）。
- **主题**：主题模式（深色/浅色/跟随系统）、强调色（6 种）、背景（纯色/极光渐变/细网格/自定义图片）、
  界面与代码字体、字号、会话列宽。改动**立即生效并自动保存**，不用点保存。

### 插件（内置）

文件与目录 / 命令行（可 sudo）/ 等待 / 交付文件 / 任务清单 / 联网搜索 / 记忆 / 技能 / 子智能体。
另外可以**自建插件**：填一段提示词 + 若干命令模板（`{参数}` 会被安全转义后替换，
或用 JSON 从 stdin 喂），就是一个新插件。

### 让用户"看见"：send_media

模型产出图片/视频/音频时用 **`send_media`**（内置插件「媒体消息」）：
传一个 http(s) 链接，或一个本机文件路径（会先复制进待下载目录），
前端就把它渲染成**看得见的图片 / 带播放器的视频 / 音频**，并带上图注与「打开」链接。
加载失败会退化成一行链接（图挂了也不至于什么都看不到）。非媒体产出（zip/pdf/txt）仍用 `deliver_file`。

### 插件与外部资源是两件事

工具表里它们都是"模型能调用的命令"，但**界面上完全分开**（需求 1）：

- **插件页**只有真正的插件（内置 9 个 + 你自建的命令模板插件）；
- **外部资源页**只有外部能力（ComfyUI / 屏幕 / 浏览器 / 你加的任何 MCP、HTTP、命令资源）。
  每张卡上能看**连接状态**、**工具清单**、**调用参数**（如 `timeout_sec`）、
  以及**它自己的提示词**（资源说明 + 每个工具的描述）——都能在这里直接改。

### 记忆也只有一个真源

记忆只有两种作用域（全局 / 某个项目），存储就是 `data/memory/` 与 `data/projects/<id>/memory/` 的 Markdown 文件。

- 「设置 → 记忆」是**汇总视图**：全局记忆 + 每个项目的记忆各一块，折叠展开后直接读写；
- 「设置 → 项目」里每个项目有一个「项目记忆」按钮，展开的**是同一块**（同一个组件、同一组接口）；
- 两边改完立刻互相可见 —— 因为读写的就是同一份文件，没有第二份副本。

### 提示词只有一个真源

「设置 → 提示词」是**全部提示词的汇总视图**：系统与循环文案、插件用法与工具描述、
记忆与技能的注入语、外部资源说明与工具描述，一共 90+ 条，可按组筛选、按关键词搜。

它和插件页/记忆页/技能页/外部资源页改的是**同一条记录**（服务端只有 `data/prompts.json` 一处存覆盖）：
在哪边改，另一边立刻看到同样的内容、产生同样的效果。每条后面标着「也能在「X 页」改」就是这个对应关系。

### 外部资源（内置预置）

| 资源 | 形态 | 说明 |
|---|---|---|
| **ComfyUI** | http | 本机 `127.0.0.1:8188`，提交工作流 / 查历史 / 取产物到待下载 |
| **屏幕操作** | mcp | [computer-use-linux](https://github.com/agent-sh/computer-use-linux)：无障碍树 + 截图 + 鼠标键盘 + 窗口，18 个工具（`screen_*`） |
| **浏览器操作** | command | [browser-use](https://github.com/browser-use/browser-use)：自然语言驱动浏览器（`browser_task`） |

**资源是通用的三种形态**（`mcp` / `http` / `command`），所以任何 MCP 服务器、任何 HTTP 服务、
任何本地命令都能接进来；界面上能看到每个资源的状态、工具清单，并有「测试连接」。

### 屏幕操作怎么用

模型**能看见屏幕**（截图作为图片消息传给模型，`deepseek-v4.1-flash` 这类视觉模型可直接读图）：

1. `screen_get_app_state` / `screen_screenshot` —— 先看；
2. 优先用**语义选择器**点击（`screen_click` 传 role/name/text，走 AT-SPI，比坐标稳）；
3. 坐标点击作为兜底；`screen_press_key` / `screen_type_text` 输入。

本机实测（2026-10-10）：GNOME 46 / X11，截图 3440×1440 正常，AT-SPI 已启用（读了无障碍树），
输入后端用 xdotool。**窗口控制后端缺一个**（GNOME 扩展没装）：
`computer-use-linux setup-window-targeting` 装上并**注销重登**后，窗口聚焦/列表才会可用。

## 让 agent 自己扩展

插件、外部资源、提示词、技能、记忆都是 `data/` 下的**文件**，agent 可以直接读、改、增，
**改完立刻生效**（服务每 2 秒检查一次，检测到变化就热加载，不用重启）：

| 想加什么 | 改哪个文件 |
|---|---|
| 插件（提示词 + 命令模板工具） | `data/plugins.json`（首次运行会种一份带示例的文件，照抄改） |
| 外部资源（mcp / http / command） | `data/resources.json` |
| 提示词 | `data/prompts.json`（只存覆盖，删掉=恢复默认） |
| 技能 | `data/skills/<名字>/SKILL.md` |
| 记忆 | `data/memory/*.md`、`data/projects/<项目id>/memory/*.md` |

系统提示词里有一段「扩展自己」告诉 agent 这些位置与纪律，细节（字段表 + 例子 + 自检清单）
放在内置技能 **`agent-modules`** 里，agent 需要时用 `use_skill('agent-modules')` 载入。
写坏了也不要紧：热加载遇到非法 JSON 会**保留内存里的旧配置**（不会把配置清空），
磁盘上还有 `<文件>.bak` 留档。

## 上游出问题时会怎样（不需要人工干涉）

循环在服务端跑，上游（模型网关）抽风不该让任务半途而废。八种故障都有明确应对，且都有测试钉着：

| 上游故障 | 应对 | 实测（假上游） |
|---|---|---|
| **半路掐断**（有内容但没给收尾标记） | 抢救已生成的内容 → 注入「接着上次的进度继续」→ **自动续跑**；连续多次仍被掐断就停下并如实说明 | 3 次调用后给出「上游连续 2 次在回答中途断开…上面保留的是已经拿到的内容」 |
| **连接被掐 / 网络错** | 识别为网络错 + 退避重试；正文保留 | 2 次调用后报错并保留半句 |
| **429 限流** | **会重试**（听上游的 `retryable`，不再拿状态码正则猜）+ **尊重 `Retry-After`** + 指数退避带 ±20% 抖动 | 第一次 429 → 重试成功 |
| **5xx / 过载** | 同上（5xx/429/408 都算可重试） | 重试后仍失败则给人话 |
| **停滞**（连上了一个字节都不吐） | **停滞看门狗**（`stallSec`，默认 90s；任何字节都算"还活着"，所以在慢慢拼长工具参数不会被误杀）→ 中止本次调用并重试 | 1 秒内识别为「停滞」并重试 |
| **空回复** | 追问最多 2 次，仍空则优雅收尾 | 3 次调用后收尾 |
| **输出反复被截断**（参数/正文不完整） | 连续 3 次就收手并说明（原先会一路问到轮次上限——实测 **86 次调用**） | 3 次调用后给出「请把任务拆得更小」 |
| **重试预算用完** | 默认**停止并报错**；把 `autoContinue` 打开就自动接着试（最多 `autoContinueMax` 次，间隔 15s） | 开启后 15s 自动续跑成功 |

三个新参数在「设置 → 模型与参数」里：`stallSec`（停滞判定秒数，0=关）、`autoContinue`（重试用完后自动续跑）、`autoContinueMax`。

**为什么 `autoContinue` 默认关**：无限自动续跑有时会掩盖真问题（比如 key 失效、额度用尽）——
那类错误重试一万次也不会好，还不如立刻告诉你。按需打开即可。

## 改了代码要重启（有自检兜底）

前端与后端是两件独立的事：**改 `src/` 之后只 `npm run build:ui` 而不重启，会出现"新前端打旧后端"**
（点新加的按钮报「没有这个接口」）。

现在有自检兜底：构建前端时会把**后端源码的内容指纹**写进 bundle，服务进程启动时也算一次
（`GET /api/version`）。两者不一致时，界面顶上会挂一条提示告诉你 `bash down.sh && bash up.sh`；
未知接口的 404 文案里也写了同一句话。`npm test` 里有一条断言盯着这个一致性。

```bash
npm run build:ui           # 改前端
bash down.sh && bash up.sh # 改后端（或前后端都改）
```

  server.ts            服务入口（node server.ts）
  src/                 后端（server/ agent/ providers/ modules/ store/ util/）
  ui/  public/         前端源码与构建产物
  resources/           外部资源的本地脚本（browser-use 的 runner 与安装脚本）

  test/                node:test 单测 + 端到端

数据可以整体拷走：`data/` 里是纯 JSON 与 Markdown（记忆是 frontmatter + 正文，与 ZCode 等工具的
记忆文件格式兼容）。想重来就删 `data/`（配置也会一起没，服务商需要重加）。

### 运行数据里的两个"非持久"设计

- **思考全文与工具明细**存在 `data/runs/<runId>/`（思考 `.md`、调用 `calls/<seq>.json`、事件 `events.jsonl`），
  界面只收摘要与计数，**点开某条时才按 `(runId, seq)` 回服务端取**（需求 7）。
- **会话在服务端跑**：关掉浏览器、换设备，运行继续跑完并落盘；重开接上继续看。

## 界面速览

- **左侧栏**（通到窗口顶部）：品牌 + 会话列表。点「+」先选项目再建会话；
  每个会话与每个项目分组后面都有**置顶**与**归档**（悬停出现）。
- **顶栏**（与左侧品牌行同高，下边框对齐）：依次是**模型连接状态**（点开改模型）、
  **项目名称**、**会话名称**，右侧是待办 / 待下载 / 设置。
- **右侧常驻待办抽屉**（16rem，可点顶栏「待办」收起）：没有清单时也留着位置并给一句说明 ——
  不然消息区会随清单出现/消失而忽宽忽窄。窄屏（<640px）不占位。
- **附件按模型发出的顺序插在正文里**：模型"先说一句 → 发张图 → 再说一句 → 发段视频"时，
  界面就是 正文 → 图 → 正文 → 视频（不是把附件堆在末尾）。做法：每次工具调用记下它出现的
  字符位置（`contentAt`），渲染时按位置把正文切段、卡片落在对应段之后；消息正文保留**所有轮**的
  叙述（而不只是最后一轮），所以中间那些"我先看看…"的话也留在转录里（主流 harness 的分段做法）。
- **正文里也能直接插图**：Markdown 的 `![说明](https://…)` 现在真的渲染成图片（点开看原图），
  站内路径也认。
- **文件卡只在真有交付物时出现**：`deliver_file`（模型把产出放进待下载目录）与资源动作抓回的文件
  会渲染成可下载的卡片；读写/列目录这类"碰过的路径"不再冒卡片（它们本来也点不动）。
- **四个区域各自滚动**：会话列表、消息区、输入框、待办抽屉互不带动；
  消息区与输入框同宽（同一列），两侧各留 20px。**默认不限宽**（窗口多宽就用多宽），
  想收窄到「设置 → 主题 → 会话列宽」（0 = 不限）。
- **归档**：「设置 → 归档」——侧栏只能归档（防手滑），恢复与**彻底删除**都在这里。
  归档一个项目会**连带归档它的会话**，返回给界面的仍是**活跃**列表（侧栏那份），所以归档后
  看到的和刷新后完全一致。
  删项目会连带删掉它的会话记录与项目记忆，但**磁盘上的项目文件一个字不动**。

## 已知边界（按需求"安全最后再考虑"）

- **没有访问控制**：绑定 `0.0.0.0` 时，同网段任何能打开页面的人都能用它操作这台机器。
  只在本机与可信内网使用；要收紧就 `HOST=127.0.0.1 bash up.sh`。
- **密码只在内存**：服务重启要重新登录（磁盘上不留密码）。
- 窗口控制后端未装（见上），子智能体不递归，`browser_task` 依赖 browser-use 的自备模型配置
  （`resources/browser-use/config.json`）。
