# 启明（Qiming）

**跑在你自己机器上的智能体。零构建、零账号、数据全在你本地。**

TypeScript 后端（Node 22 原生类型剥离，无需编译）· React 19 前端 · 单机单进程

</div>

---

## 这是什么

启明是一个**独立的本机智能体**：给它一个模型（任意 OpenAI / Anthropic 兼容网关），它就能在你机器上读写文件、
执行命令、调外部服务、跑子任务 —— 并且**从头到尾都在你的控制之下**。

它不是某个云服务的客户端，也没有"平台"。服务跑在你的机器上，数据存在工程目录里，
登录用的就是你自己的系统账号，命令以你的身份执行，`sudo` 随便用。

```
                        ┌──────────────────────────────────────┐
   浏览器  ──HTTP/SSE──▶ │  启明（node server.ts，本机进程）      │
                        │   循环 / 工具 / 记忆 / 技能 / 资源     │
                        └───────────────┬──────────────────────┘
                                        │（你的 API Key）
                                        ▼
                                 你选的模型网关
```

## 优势

### 1. 用户完全可控

- **没有账号体系**：登录 = 用本机系统账号的密码（校验方式就是 `sudo -v`）。密码只存在服务进程内存里，
  磁盘上不留密码、没有会话表，重启即失效。
- **没有工具白名单、没有访问级别**：登录后模型能做的事，就是你自己能做的事。
- **服务端不设硬上限**：轮次、并发、命令条数、超时、上下文窗口……你在界面上填多少就是多少。
  真跑飞了，点界面上的「停止」中断。曾经有过"用户填 300 实际静默只跑 200"的坑，
  现在规则被收敛到一处纯函数并用单测钉住。
- **全部开关都在界面上**：模型、系统参数、插件启停与参数、外部资源、提示词、技能、记忆、主题 ——
  没有任何"只能改配置文件"的隐藏设置。
- **不强绑任何厂商**：任何 OpenAI 兼容或 Anthropic 兼容的网关都能接，接口地址、模型名、API Key 自己填。

### 2. 自维护：agent 能改自己

插件、外部资源、提示词、技能、记忆这五样东西，在本机都是 `data/` 下的**文件**，
模型可以自己读、自己改、自己加，**改完立刻生效**（服务每 2 秒检测一次，热加载，不用重启）：

| 想加什么 | 改哪个文件 |
|---|---|
| 插件（提示词 + 命令模板 = 新工具） | `data/plugins.json` |
| 外部资源（MCP / HTTP / 本地命令） | `data/resources.json` |
| 任意一条提示词（含工具描述） | `data/prompts.json` |
| 技能（SKILL.md 目录） | `data/skills/<名字>/SKILL.md` |
| 记忆 | `data/memory/*.md` |

系统提示词里就写着这些位置和纪律。写坏了也不怕：热加载遇到非法 JSON 会**保留内存里的旧配置**，
磁盘上还留一份 `<文件>.bak`。

也就是说，**你可以直接对启明说「给我加个查天气的工具」，它会自己去改自己的配置。**
源码本身也是它自己能改的（"改你自己" = 改这个工程）。

### 3. 极致精简

- **后端零构建**：Node 22 的原生 TypeScript 支持直接跑 `.ts`，没有 webpack / 没有 tsc 产物 / 没有 `dist/`。
  改完后端源码，重启进程即可。
- **前端只有一个 esbuild 命令**：`npm run build:ui`，产物是 `public/` 里的两个文件。
- **依赖极少**：运行期只有 3 个依赖（`diff` / `gpt-tokenizer` / `simple-git`），
  前端只有 React。整个后端 600KB 量级。
- **没有数据库**：一切都是 JSON 与 Markdown 文件，可以整体拷走。
- **单进程**：没有微服务、没有消息队列、没有 docker-compose。

### 4. 看得见、留得住

- **思考与操作明细不进浏览器内存**：SSE 只发摘要与计数；思考全文、工具参数与结果存在服务端
  `data/runs/<runId>/`，点开某条消息时才按 `(runId, seq)` 回取。刷新页面不掉状态。
- **运行在服务端**：关掉浏览器、换台设备，任务照跑完并落盘；重开接上继续看。
- **文件改动可回看、可撤回**：每次写文件前自动打检查点，界面上能看 diff、能一键回到改之前。
- **上游抽风有兜底**：截断、断连、429、5xx、停滞（一个字节都不吐）、空回复、输出反复被截断 ——
  八种故障各有明确应对与测试，不需要人盯着。

### 5. 开箱即用的完整能力

不用配置插件体系就能干活，内置 11 个插件与 3 个预置外部资源：

**插件（工具）**：文件与目录 · 命令行（可 sudo）· 等待 · 交付文件 · 媒体消息 · 任务清单 ·
联网搜索 · 记忆 · 技能 · 子智能体 · 改动比对与撤回

**外部资源**：ComfyUI（生图/工作流）· 屏幕操作（无障碍树 + 截图 + 鼠标键盘）· 浏览器操作（自然语言驱动）

## 快速开始

### 环境要求

- **Node.js ≥ 22.6**（用它的原生 TS 支持直接运行 `.ts`；`node -v` 确认）
- Linux（已在 Ubuntu 24.04 上验证；屏幕/桌面相关能力需要图形会话）
- 一个可用的模型网关（OpenAI 或 Anthropic 兼容）及其 API Key

### 三步跑起来

```bash
git clone <你的仓库地址> qiming && cd qiming

bash up.sh          # 首次会自动装依赖、构建前端，然后启动
# 打开 http://127.0.0.1:8787/ ，用本机账号密码登录
```

启动后：

1. **设置 → 模型**：点「添加服务商」，填 Base URL、模型名、API Key（见下方[必填清单](#你需要填什么)）；
2. **设置 → 项目**：选一个目录当工作区（会话的默认工作目录）；
3. 回主界面，直接说话。

> `up.sh` 默认监听 `0.0.0.0:8787`（手机/其它设备也能连）。
> 只给本机用就 `HOST=127.0.0.1 bash up.sh`；关掉登录用 `QIMING_AUTH=off bash up.sh`。

停止：`bash down.sh`。改完后端代码后重启：`bash down.sh && bash up.sh`。

## 你需要填什么

以下是**必须你自己提供**的内容。仓库里对应的位置一律留空或写成占位符 ——
请勿把你自己的密钥提交进版本库。

### 1）模型服务商（必填，否则无法对话）

在「设置 → 模型 → 添加服务商」里填：

| 字段 | 说明 | 示例 |
|---|---|---|
| 类型 | `openai`（Chat Completions 兼容）或 `anthropic` | `openai` |
| Base URL | 网关地址，**带 `/v1`** | `https://api.deepseek.com/v1` |
| 模型名 | 上游的模型标识 | `deepseek-chat` |
| API Key | 你的密钥 | `sk-你的密钥` |

> 只要能说 Chat Completions 或 Anthropic Messages 协议就能接：官方 API、自建网关、中转站、本地
> vLLM / Ollama 都行。若你的网关需要额外请求头（例如某些平台的会话头），在服务商的「请求头」里加。
> 支持视觉的模型可以直接看图（截图会作为图片消息发给它）。

### 2）联网搜索（可选）

内置的「联网搜索」插件通过一个**本地搜索 CLI** 工作，需要你自己指路：

| 参数 | 说明 |
|---|---|
| CLI 路径 | 搜索脚本的绝对路径（默认留空 = 该插件不可用） |
| Python 解释器 | 默认 `python3` |
| API Key | 搜索服务的 Key；留空则匿名（限额更低） |
| 单次搜索超时 / 每次运行最多调用次数 | 自行设定 |

### 3）外部资源（按需）

| 资源 | 需要你提供 | 不装会怎样 |
|---|---|---|
| **ComfyUI** | 一个在跑的 ComfyUI 地址（默认 `http://127.0.0.1:8188`） | 显示"未连接"，其余功能不受影响 |
| **屏幕操作** | 无需密钥；GNOME 下需启用无障碍（界面给了一键安装脚本提示） | 无法操作桌面应用 |
| **浏览器操作** | `bash resources/browser-use/install.sh` 一次；没配模型时会自动回落用你的服务商设置 | 无法操作浏览器 |

### 4）网络代理（可选，中国大陆常见）

如果你的网络需要代理才能访问外部服务：

- 模型网关、搜索 CLI 的代理：按各工具自己的配置走环境变量（`HTTPS_PROXY` 等）；
- 浏览器资源：在 `resources/browser-use/config.json` 里填 `"proxy": "http://127.0.0.1:7890"`；
- 本机自建代理（如 mihomo）的接入脚本见 `resources/proxy/`，端口在脚本参数里配。

### 5）环境变量（可选）

| 变量 | 默认 | 作用 |
|---|---|---|
| `PORT` | `8787` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址（`127.0.0.1` 只允许本机） |
| `QIMING_AUTH` | 开 | 设 `off` 关闭登录（自动化/完全信任场景） |
| `QIMING_WORKSPACE` | `~/workspace` | 默认工作区根目录 |
| `QIMING_DATA` | `<工程>/data` | 数据目录位置 |
| `QIMING_MAX_RUNS` | `8` | 同时运行的会话数上限（`0` = 不限） |

## 目录结构

```
qiming/
  server.ts           服务入口（node server.ts）
  src/
    server/           HTTP / SSE / 路由 / 运行注册表 / 运行宿主
    agent/            循环内核、提示词组装、上下文、工具执行、子智能体
    providers/        openai / anthropic 适配
    modules/          插件 / 记忆 / 技能 / 资源 / 提示词 五大模块
    store/            原子读写、会话、项目、设置
    util/             路径、日志
  ui/                 React 源码（features/ state/ lib/）
  public/             前端构建产物（只入库 index.html）
  resources/          外部资源的本地脚本（browser-use、proxy）
  data/               运行数据（不入库）
  test/               单测 + 端到端 + 真机界面检查
  ARCHITECTURE.md     架构设计（改代码前先读它）
```

数据目录 `data/` 的布局：

```
data/
  settings.json       服务商与参数（含 API Key —— 注意本机权限）
  sessions.json       会话列表        projects.json  项目
  plugins.json        插件覆盖        resources.json 外部资源
  prompts.json        提示词覆盖      skills.json    技能索引
  memory/             全局记忆        projects/<id>/memory/  项目记忆
  skills/<名字>/SKILL.md             技能正文
  runs/<runId>/       思考全文、工具明细、事件流
  checkpoints/        文件改动检查点    downloads/     待下载产物
```

**想重来就删 `data/`**（配置会一起没，服务商需要重加）。整个目录可以拷到另一台机器。

## 参数与自定义

### 设置 → 模型（这次请求发什么）

| 参数 | 说明 |
|---|---|
| temperature | 采样温度 |
| maxTokens | 单次回复上限 |
| thinkingBudget | 扩展思考预算（Anthropic） |
| callTimeoutSec | 单次模型调用超时（秒） |
| retryCount | 上游报错自动重试次数 |
| ctxLimit | 上下文窗口上限（token），`0` = 不压缩 |
| echoThinking | 是否把思考回传（少数网关需要） |

### 设置 → 系统（智能体怎么跑）

| 参数 | 默认 | 说明 |
|---|---|---|
| `maxRounds` | `0`（自动） | 单次运行轮次上限，**无硬封顶**；自动 = 各插件额度之和 + 2 |
| `maxRuns` | `8` | 同时运行的会话数，`0` = 不限 |
| `stallSec` | `90` | 停滞看门狗：这么久没任何字节就中止并重试（`0` = 关） |
| `autoContinue` | 关 | 重试预算用完后自动接着试 |
| `autoContinueMax` | `3` | 自动续跑上限 |
| `spillEnabled` / `spillMaxChars` / `spillHeadChars` / `spillTailChars` | 开 / 24000 / 4000 / 4000 | 超长工具结果落盘，只把「头尾预览 + 路径」回灌给模型 |
| `checkpointLimit` | `200` | 改动检查点列表最多列多少条（`0` = 全列） |
| `queueDefault` | `queue` | 运行中发消息的默认语义：排队 / 插队 / 立即执行 |

### 设置 → 项目

工作区根目录 + 项目列表。**一切项目都必须在工作区之下**（界面目录选择器只在工作区内浏览，
服务端接口再校验一遍）。项目可改名、可改路径（不搬动磁盘文件）。
工作区默认值不写死任何路径：优先 `QIMING_WORKSPACE`，其次 `~/workspace` 的上一级，最后家目录。

### 设置 → 插件 / 外部资源 / 提示词 / 技能 / 记忆

五个模块各有一个页面，且**提示词只有一份真源** —— 在插件页改工具描述，提示词页同一条立刻同步，
因为读写的就是同一条记录（`data/prompts.json`）。

### 自建能力的三条路

1. **自建插件**：一段提示词 + 若干命令模板（`{参数}` 会被安全转义后替换，或用 JSON 从 stdin 喂），
   就是一个新工具 —— 不用写代码。
2. **接外部资源**：`mcp`（填启动命令）/ `http`（Base URL + 动作）/ `command`（一条命令模板）。
   任何 MCP 服务器、任何 HTTP 服务、任何本地脚本都能接进来。
3. **改源码**：整个工程就是它自己，模型能读能改（见下方[自维护](#2-自维护agent-能改自己)）。

### 设置 → 主题

深色/浅色/跟随系统、强调色（6 种）、背景（纯色/极光渐变/细网格/自定义图片）、
界面与代码字体、字号、会话列宽。改动立即生效并自动保存，没有"保存"按钮。

## 四个模块

| 模块 | 是什么 | 界面位置 | 模型怎么用 |
|---|---|---|---|
| **插件** | 提示词 + 可执行命令（工具） | 设置 → 插件 | 提示词注入系统消息，工具进工具表 |
| **记忆** | AI 工作的重要记录 | 设置 → 记忆 | 索引常驻，`memory_read` 取全文 |
| **技能** | 具体工作方法（SKILL.md） | 设置 → 技能 | 目录常驻，`use_skill` 载入全文 |
| **外部资源** | 本机可调用的外部能力 | 设置 → 外部资源 | 工具进模型工具表 |

四块都可读可写，改完立刻生效。记忆只有两种作用域（全局 / 项目），存储就是 Markdown 文件，
与其它工具的记忆格式兼容。

## 安全边界（请务必读）

本工程按"**单机、单用户、完全信任**"设计：

- **没有访问控制**。绑 `0.0.0.0` 时，同网段任何能打开页面的人都能用它操作这台机器。
  只在本机与可信内网使用；要收紧就 `HOST=127.0.0.1 bash up.sh`。
- **登录即系统账号**，因此**能登进来的人就有你的 sudo 权限**。别把它暴露到公网。
- **`data/settings.json` 里是明文 API Key**（还有 `resources/browser-use/config.json` 可能的明文密钥）。
  这些文件已在 `.gitignore` 中，**请勿提交**；机器本身也应是可信的。
- 密码只在内存：服务重启要重新登录。
